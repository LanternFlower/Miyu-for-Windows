## 一、原则:先量尺后动手,零字节变化

- **改提示词 / 工具面之前先建量尺**。`agent/tests/request_shape.rs` 的 `request_shape_probe`(ignored,
  `MIYU_REQUEST_SHAPE_OUT=/tmp/x.json cargo test --lib request_shape_probe -- --ignored`)把五张脸(dev-owner、
  normal-owner、normal-owner-voice、normal-external、normal-internal)的 system 提示词 + 消息序列 + 工具名单落成 JSON,
  重构前后 diff。归一化:临时目录路径、工具名排序、运行时戳。任何「应该零字节变化」的重构都拿它证明;
  字节该变的(语音协议随开关)也拿它证明只变了那一段。
- **门禁是唯一的验收**:`bash test_scripts/refactor-check.sh` 五道(格式不退步、编译零警告、用例数不减、
  模型面无中文、文件规模不涨)+ `python3 test_scripts/arch_dep_check.py`(层序)。全绿才算完成,「大致完成」不算。
- **删冗余先确认**:架构改动后的可删项攒清单(`docs/plan/2026-09-16-dead-code-inventory.md`),用户拍板再删。
  死代码用编译器裁决,分两阶段:先全部标 `#[cfg(test)]` 保编译,再在测试构建下查,连测试都不用的才删。
- **别把「只有测试在用」等同于「死」**:104 项里 75 项是测试夹具(测试拿它们摆状态去测活代码),删了就是删覆盖。
  裁决法:把它们整体删掉跑 `cargo check --tests`,按编译错误的封闭函数归类,再逐个看函数体——薄包装就把测试
  调用点改成直接调生产函数,独立死逻辑才连测试一起删。

## 二、层序与拆 crate

- 原来的依赖门禁只是一张**禁止对**表(llm 不许 use web 之类),顶层模块图实际有一个 28 模块的强连通分量。
  「门禁绿 = 无环」是错觉。现在的 `TIERS` 是完整层序:同层互引允许,低层引高层违规,新顶层模块必须登记。
- 烧逆向边的顺序:先给门禁上完整层序 + 把现存违规写成**带理由的白名单**(reason = 要做的那件事),再逐条烧。
  多数逆向边是几个基础设施放错了地方(`workspace` task-local、`sandbox`、宿主端口、文本宽度工具、id 生成器),
  下沉成基础模块就断了;真正要设计的只有 `agent → platforms`(改成 agent 自己定义的窄 trait,平台层实现)。
- 拆 crate 的形状:根包 `miyu` 留原地(打包脚本读根 `[package].version`,PKGBUILD 的 `cargo build --release`
  与 `target/release/miyu` 都不用改),下面四层住 `crates/`。**只搬 `.rs`**,非 rs 资源留 `src/` 原处,
  `include_str!` 相对路径按新位置重算。`OUT_DIR` 是每个 crate 各自的,资源产物(jieba 索引)由 base 以 `pub const` 导出;
  `concat!(env!(...))` 跨不了 crate,改运行时 `format!`。**构建 id 不能烘进 base**:它要对整棵源码树 rerun,
  烘在 base 就等于改任何一层都从 base 起全量重编(第一版就是这么写的,增量量尺跑出来才发现);
  改成根包 `build.rs` 算、入口 `install_build_id` 装、下层运行时读 `build_id()`。
- 可见性放宽**只放宽编译器点名的**(`scratchpad/fix_visibility.py` 那套:E0603/E0624/E0364/E0451/E0616 循环到零),
  别批量 `pub(crate)` → `pub`。坑:定义位置在 note 子诊断里(message 含 "defined here",span 无 label);
  定义位置是 `pub use x::*` 时真正要放宽的是子模块里的条目,按名字找;trait 方法不能带可见性(E0449),误加了要回退。
- 跨 crate 的测试夹具:`#[cfg(test)]` 的东西对别的 crate 不存在。夹具集中在各模块 `test_support.rs`(`mod test_support` 必须私有,
  否则 `pub use a::*; pub use b::*;` 之间 `test_support` 名字歧义);上游 crate 的测试要用下游的真实现时,`[dev-dependencies]` 指回去(dev 依赖允许成环)。
- **测试态行为开关也一样**:拆完第一次全量测试红了 17 条,全是下层 crate 里 `cfg!(test)` / `#[cfg(not(test))]` 的开关在上游测试里失效——
  `miyu_executable` 的防 fork 炸弹闸关了(embedding worker 把测试二进制当 miyu 起了)、终端探测走了真路径、渲染真起子进程、
  `CARGO_MANIFEST_DIR` 变成 `crates/<crate>` 找不到 `src/scripts` 与 `assets/fonts`。全部改成 `cfg(any(test, feature = "testkit"))`
  + `miyu_base::WORKSPACE_ROOT`。测试态下闲置的生产路径(worker 子进程)用模块级 `#![cfg_attr(any(test, feature = "testkit"), allow(dead_code))]`。
- 量尺:本机没有 `/usr/bin/time` 和 `bc`,峰值内存读 cgroup 的 `memory.peak`(`scratchpad/measure_build.py`)。
  拆前基线:改 agent 一行 check 18 s、改 cli 一行 build 42 s、`cargo test --no-run` 峰值 18.4 GB、release 68 MB。

## 三、委派机械活给便宜模型

- 施工单写死四样:硬约束(路径、cgroup、一次一个 cargo、不 commit/stash/cargo fix)、逐步命令、验收三件套、
  「锚点对不上就停下报告,别猜」。三批 Opus 子代理都是一次过,还各自照实报出施工单的估算偏差
  (传递闭包比估的大、`git mv` 暂存导致 `git diff` 漏改名)。
- 判断题留给自己:哪个函数该住哪一层、trait 怎么抽、测试是删还是搬。子代理报上来的「备选方案」要认真看,
  第三批那条(`random_id` 归基础层)就是它提的。
- cargo 一次只能跑一个(内存),所以子代理只能串行派;派出去之后自己别碰会被编译的文件,门禁复核等它交回再做。

## 三之二、千行函数怎么拆(B 批,09-17)

- 先把循环外的局部量收成一个状态结构(`RoundState` / `RemoteRepl`),用脚本按标识符改写 `x` → `st.x`(只改代码行不改注释,
  排除 `x:` 这种字段标签),编译一次;然后按锚点逐块切成方法,一两块编译一次。`continue` / `break` / `return` 变成枚举返回值
  (`RoundRecovery::{Retry,Fail}`、`ToolBatchOutcome::{Truncated,Executed}`、`LoopStep::{Continue,Break}`),match 臂里裸的
  `=> continue,` 别漏。`async fn` 里不能 `continue` 外层循环,编译器会点名。
- 量尺不变是唯一的正确性证明:`request_shape_probe` 五张脸拆前后逐字节相同,定向测试用例数与结果逐项对齐。
- 同一棵 worktree 只能有一个会话动手。09-17 另一个会话按用户要求 rebase 这棵树,`git add -A` 把我正在写的半成品扫进提交又摘出来,
  `checkout` 冲掉了未暂存改动。发现时立刻整树打 tar 快照,`ListAgents` / `SendMessage` 直接跟对方会话说清边界(别动哪个目录、
  做完回一句),等它安静再接。对方只跑 `cargo build` 不跑 `--all-targets` 会漏测试里的路径错误。

## 四、工具坑(每条都真撞过)

- **grep 管 `head` 会截掉后半段**,据此下「生产从不读」这种结论会误报(白名单那次)。跨行的字段访问
  (`.plugins\n.skills`)单行 grep 匹配不到,要按字段名跨行搜。
- **worktree 里 `cd` 到别处会把后续命令的工作目录重置到主检出**,cargo 会跑错树。一律绝对路径,不 `cd`。
- `cmd | python3 - <<'EOF'` 的 heredoc 会顶掉管道 stdin,解析器要写成文件再跑。
- python 补丁脚本半途失败会留下半成品:重跑前先 grep 现状,别再跑一遍同一个脚本;锚点用 `count == 1` 断言;
  `cargo fmt` 会改排版让锚点失效;Rust 源里的 `\n` 字面量用 raw string 匹配;正则 `^\s*` 会吃掉换行,
  让函数起始行早一行(删测试时把上一个函数的 `}` 一起删了)。
- 删 `use` 行要连它头上的 `#[cfg(test)]` 一起删,否则标记落到下一行 `use anyhow` 上,整个模块 `bail!` 全炸。
- `git mv` 会暂存改名,检查点要用 `git diff HEAD` 而不是 `git diff`。
- pyte 抓帧前先确认目标在滚动视口里(按 End、看表头计数),别一上来怀疑二进制或配置——
  为一个 40 行视口裁掉的分组重建了两次二进制。
- 全屏 TUI 探针要答 `ESC[6n`,否则随后的按键被当成光标应答吞掉。

- **`cargo test` 之后 `target/debug/miyu` 不是生产二进制**:集成测试要 `CARGO_BIN_EXE_miyu`,cargo 用测试构建统一后的特性集
  (dev-deps 打开的 `testkit`)重链了它,测试态开关(终端探测、OSC 8、进程内 embedding)全是假的。跑黑盒 / 探针前一律先 `cargo build`。
