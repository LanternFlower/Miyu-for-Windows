# 15 · 扩展指南

> ⚠️ **临时版本提示**：本文档由 DeepSeek 根据当前 Miyu 源码逐行整理，属于临时参考版本；正式版文档仍在施工中，内容可能与最新代码存在出入。请以 `miyu -h`、`miyu config`、仓库 README 及源码为准。

Miyu 提供了五层扩展入口，从“完全不用写代码”到“写协议适配器”，按成本排序。

## 1. 不改代码的扩展（推荐先试）

| 想加什么 | 怎么做 |
|---|---|
| 新知识 | `miyu kb add`，或直接让 AI `upload_text_to_knowledge_base` |
| 新流程/能力 | 让 AI `create_skill` → 草稿 → `publish_skill`，按 `src/skills/skill-creator.md` 规范 |
| 新脚本工具 | 把可执行文件放进 `~/.miyu/data/scripts/`，让 AI `register_script` 填写参数 JSON |
| 新表情 | 给 AI 图片路径，`add_meme` 自动识图入库 |
| 新人格 | `miyu config` → 自定义提示词 → 新建 persona |
| 新主题 | 把 matugen 生成的 `webui-theme.css` 放到 `~/.miyu/config/webui-theme.css` |
| 新 MCP 工具 | 配置 `mcp.servers`（stdio server），工具自动注册 |

## 2. 新增一个 Rust 内置工具

步骤：

1. 新建 `src/tools/my_tool.rs`，实现：

```rust
pub fn register(registry: &mut ToolRegistry, config: AppConfig) {
    registry.register(
        ToolSpec::new("my_tool_name", |ctx| async move {
            // 返回 serde_json::Value 或 anyhow 错误
            Ok(serde_json::json!({"ok": true}))
        })
        .writes()                        // 只读就不要
        .with_display_name("我的工具")
        .with_always_loaded(false)
        .with_load_policy(LoadPolicy::Summary)
        .with_groups(&["utility"])
        .with_timeout_seconds(Some(30)),
    );
}
```

2. 在 `src/tools/mod.rs` 顶部加 `mod my_tool;`，并在目标注册表里调用：

- Normal：`builtin_registry`（`tools/mod.rs:338` 起）
- Dev：`dev_registry`（`tools/mod.rs:498` 起）
- QQ 受限平台：`restricted_platform_registry`（`tools/mod.rs:540` 起）

3. 在 `src/tools/tool_descriptions.rs` 的宏里加 `include_str!("descriptions/my_tool_name.json")`。
4. 新建 `src/tools/descriptions/my_tool_name.json`：

```json
{
  "name": "my_tool_name",
  "display_name": "我的工具",
  "description": "……",
  "parameters": { "type": "object", "properties": {}, "required": [] },
  "always_loaded": false,
  "load_policy": "summary",
  "groups": ["utility"],
  "timeout_seconds": 30
}
```

5. 在 `tools/mod.rs` 的 `builtin_readable_tool_name` 加中文名；新组在 `builtin_readable_group_name` 加组名，并加到 `descriptions/groups.json`。
6. 若需要配置开关，在 `config.rs` 的 `PluginsConfig` 加字段、默认值、校验、TUI 表单。
7. 若需要子代理继承，必须在 `let task_tools = registry.clone();` 之前注册。

**关键坑**：

- 描述以 JSON 为真相源，Rust 里的 `description` 只是占位。
- 权限只由 `.writes()` / `.presentation()` 决定，JSON 的 permission 字段不生效。
- 懒加载 stub 会以“一句话摘要 + 宽松参数壳”常驻；完整 schema 通过 `load_tools` 返回，不要为了显示完整参数把工具设成 always_loaded（会破坏前缀缓存）。

## 3. 新增一个用户技能

直接看 `src/skills/skill-creator.md`。核心规范：

- frontmatter 必须有 `name`（小写 ASCII/数字/连字符）和 `description`（触发条件写清楚）。
- `allowed-tools` 只是兼容性元数据，**不授权限**。
- 使用 `create_skill`/`update_skill` 生成草稿，用 `apply_patch` 写文件，最后 `publish_skill` 原子发布。
- 脚本是资源，发布 skill 不会自动把脚本注册为工具。

## 4. 新增通讯平台（PlatformAdapter）

Miyu 的平台核心是通用的，OneBot 只是第一个实现。步骤：

1. 新建 `src/platforms/<name>.rs`，在 `platforms/mod.rs` 声明模块。
2. 实现 `PlatformAdapter` trait（`platforms/types.rs:404-508`）：
   - 必须实现 `send` 和 `bot_display_name`；
   - 按能力覆盖 `message_info`、`fetch_platform_file`、`group_members`、`set_group_ban`、`delete_message` 等；不覆盖有明确的 not-supported 错误。
3. 把协议入站事件转成 `PlatformInboundEvent`（`types.rs:176-216`），填 platform/account/conversation/position/ingress_order/text/media。
4. 用 `resolve_platform_session`（`platforms/mod.rs:1564`）拿会话，再调 `run_platform_turn`（`mod.rs:2094`）；排队/抢占用 `PlatformRuntime::acquire_session_turn/preempt_session_turns`。
5. 出站消息用 `OutboundSegment::{Markdown,Text,Mention,ImageBytes,ImagePath,FilePath}` 和 `OutboundBody::{Segments,Forward}`，按你平台的能力序列化。
6. 新平台命令在 `platforms/commands.rs` 加描述符、解析与权限；新平台工具在 `platforms/tool.rs` 注册。
7. 配置：在 `config.rs` 的 `PlatformsConfig` 加平台块；平台插件通过通用 `PlatformPlugin` trait 可复用。

注意当前仍有少量 OneBot 特化：`access_control.rs` 的 onebot 平台名、`file_reader.rs` 的 `platform_files/qq` 路径、`qq_mention_users` 等。做多平台支持时需要参数化。

## 5. 新增平台插件

插件 trait 在 `platforms/plugins/mod.rs:257-407`：

```rust
#[async_trait]
impl PlatformPlugin for MyPlugin {
    fn descriptor(&self) -> PluginDescriptor {
        PluginDescriptor { id: "my_plugin", priority: 150, default_enabled: true }
    }
    // 按需覆盖 hook：
    // observe_ingress / handle_command / register_tools / preempt_inbound
    // turn_started / observe_inbound / decide_trigger / before_turn
    // before_send / after_send / after_session_reset / after_persona_reset ...
}
```

然后在 `built_in()` 注册，并加配置块 `platforms.qq.plugins.<id>`。

Hook 契约：

- `memory_content` 插件禁止改；`system_context` 必须字节稳定，动态内容走 `turn_system_context`。
- `before_send` 默认 `PreparedSend::unchanged`；改过 metadata 会自动补 fallback；转图/转发类插件应显式给 `fallback=原消息`。
- 固定输出可用 `send_fixed_tool_output` 旁路整个插件链，并压制后续模型回复。

## 6. 新增 LLM 供应商协议/能力

- 协议类型：`ProviderProtocol`（`llm/openai_compatible.rs:370`），已有 chat / responses / anthropic。
- 新协议要扩展：`from_provider`、`effective_protocol`、`chat_stream_single`、请求结构、SSE 解析、usage 归一化。
- 新 capability：`provider_capabilities.rs` 只持久化 false 条目；运行时能力位在客户端结构里建模。
- 新 usage 字段：`Usage` → `normalize_cache_fields` → cache log / usage 明细同步。
- 错误分类/冷却：`classify_provider_error_body`、`cooldown_for_status/error`、`endpoint_failover_allowed`、`same_endpoint_retry_allowed`。

## 7. 新增配置项

1. `config.rs` 的结构体加 `#[serde(default...)]` 字段。
2. `Default` 或 `default_xxx()` 给默认值。
3. `validate()` 加校验。
4. 需要 normalize/迁移时在 `migrate`/`normalize_*` 处理。
5. TUI：主菜单入口、插件字段（`config_tui.rs` 的 `plugin_fields`/`apply_plugin_fields`）、或全局设置表单（`edit_settings` 字段只能**追加末尾**，有 debug_assert 锁数量）。
6. 加测试。

## 8. 新增 REPL 斜杠命令

1. `ReplSlashCommand` 枚举加变体（`cli.rs:13505` 附近）。
2. `REPL_COMMAND_TABLE` 登记：自动获得补全、唯一前缀解析和 `/help` 展示。
3. `parse_repl_input` 不需要大改（走表）。
4. 在远程 dispatch（约 `cli.rs:7407`）和直连 if 链（约 `cli.rs:8384`）加分叉。
5. 避免制造前缀歧义（如 `/p` 同时是 `/persona` 和 `/pop`）。

## 9. 改 WebUI

- 静态文件 `web/index.html`、`web/styles.css`、`web/app.js` 通过 `include_str!/include_bytes!` 嵌入，**改完必须重新 build**。
- 后端新路由：`web.rs` 的 router（3736 附近）；读接口 `require_auth`，写接口 `require_mutation`。
- 新 SSE 事件：`RunEventMapper` 映射，事件必须带 run_id，否则被过滤。
- 前端主题：在 `styles.css` 加 `body[data-theme="..."]` MD3 token 块，并同步主题按钮。
- CSP 是 `script-src 'self'; style-src 'self'`，内联脚本/样式会被拦截。

## 10. 改渲染/回复处理

- 终端 Markdown 语法：`render_inline`、`render_line`；新工具摘要：`tool_subject`。
- 数学公式：`render/math.rs` 的 `symbol_for`、`convert_command`、`unicode_math_lines`。
- QQ 长图渲染：`platforms/plugins/renderer.rs`；主题/块类型/分列/worker 协议都在里面。
- 默认阈值/主题等在 `reply_processor.rs` 的 `ReplyProcessorConfig`。

## 11. 数据库结构变更

1. 在 `state/migrations.rs` 的 `MIGRATIONS` 末尾追加 `v25`，并升 `LATEST_VERSION`。
2. 轻量加列用 `add_column_if_missing`；重建表参考 v2。
3. 新表加 CREATE + 索引，并在 `StateStore`/`ConversationDb` 加薄委托。
4. 改 `Turn` 字段必须同步所有固定列序 SELECT 与 `map_turn_row`（最脆弱处）。
5. 迁移在 immediate 事务内跑并做 `pragma_foreign_key_check`。

## 12. 修改前先问自己的问题

- 这个改动会不会让同一会话的请求字节发生变化？（改提示词、工具目录、消息顺序都是高危。）
- 这个内容该进 `raw_content`、`display_content` 还是 sidecar？
- 权限是我在代码里判，还是试图让提示词“自觉”？
- 删除操作是否默认回收站、是否先确认？
- 新工具在 dev / QQ 受限平台该不该出现？
