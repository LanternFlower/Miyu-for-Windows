# 14 · 参与开发

> ⚠️ **临时版本提示**：本文档由 DeepSeek 根据当前 Miyu 源码逐行整理，属于临时参考版本；正式版文档仍在施工中，内容可能与最新代码存在出入。请以 `miyu -h`、`miyu config`、仓库 README 及源码为准。

## 1. 环境要求

- Rust 1.89+（`rust-version = "1.89"`）
- Linux 桌面（当前主要支持 Arch；macOS 部分适配，Windows 仅部分通知/平台代码）
- 可选依赖：`chafa`、`ripgrep`、`git`、`fish/bash/zsh`
- 字体：系统包提供 Noto CJK/Emoji；源码开发时字体目录会回退到 `assets/fonts`

## 2. 构建与运行

```bash
git clone https://github.com/SHORiN-KiWATA/Miyu.git
cd Miyu
cargo build                 # debug
cargo run -- miyu --help    # 注意二进制名是 miyu
cargo build --release
```

release profile：`lto = "thin"`、`strip = "symbols"`。

### build.rs 生成的东西

修改这些文件后必须重新构建：

- `src/prompts/{miyu.md,miyu.hint.md,miyu-dialogs.md}` → XOR + base64 后编译进二进制（默认人格）。
- `assets/o200k_base.tiktoken` → 紧凑 o200k BPE 词表。
- `assets/jieba/dict.txt` → FST 紧凑词典（记忆分词）。
- `src/`、`web/` 任一文件变化都会生成新的 `MIYU_BUILD_ID`，CLI 用它判断 daemon 是否需要重启。

## 4. 代码地图（源码 src/）

里；**每个文件开头的 `//!` 说明它为什么单独存在**，找东西先读那一段。

### 文件规模基准

量出来的，不是拍的：18 个公认高质量 crate 的 1095 个源文件，中位数 183 /
P90 935 / P95 1412。于是 **目标 800、上限 1500、红线 2000**。

`bash scripts/refactor-check.sh` 一次跑完五道检查（格式不退步、编译、用例数
不减少、文件规模、依赖方向）。改完代码跑一遍，红了就别提交。

## 5. 修改前的四条铁律（务必读）

1. **前缀即契约**：消息组装路径、工具目录、提示词必须是字节确定的；不要插入动态时间戳到历史中段。
2. **Append-only**：上下文只准尾部追加；压缩是唯一例外且必须单调。
3. **权限由代码承担**：不要在提示词里“授予”权限；真实鉴权在 `platforms/access_control.rs` 和执行层。
4. **三份内容分离**：`raw_content` 只给记忆用；不要往里面塞工程 XML/时间戳。

违反前两条的改动，测试可能不报错，但会让长会话缓存命中悄悄归零、费用暴涨。相关回归测试和 mock 前缀断言见 `docs/cache-and-prompt-plan.md`。

## 6. 提交流程建议

- 小修：直接提交，说明动机与影响。
- 新工具/新配置：同时改描述 JSON、配置默认/校验、TUI（如需要）和测试。
- 涉及消息组装/工具目录/提示词：先跑 `cargo test`，再手测两轮请求的 cache log（`cache-usage.*.jsonl`），确认第二轮的 `cache_read` 没有异常下降。
- 版本发布：按 `packaging/README.md` 流程升版本、打 tag、构建包。
- 许可证：MIT，第三方字体/词表/表情等见各自 LICENSE。

## 7. 开发小贴士

- `miyu daemon logs request` 能实时看每个出网请求的 provider/model/scope/token/KB。
- `MIYU_LOG=debug` + `--debug` 看完整本地日志。
- `MIYU_HOME=/tmp/miyu-test` 隔离测试数据，不会碰你的真实配置。
- 修改 WebUI 静态资源后必须重新编译（文件是 `include_str!`/`include_bytes!` 嵌入的）。
- 测试渲染 worker 时不需要真显示器；`__renderer-worker` 可以独立跑。
