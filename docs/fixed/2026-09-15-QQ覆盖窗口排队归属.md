# QQ 覆盖窗口内旧排队回合未失效

状态：2026-09-16 用户验收通过，授权分项提交并合并 main。

已证明的路径：同发送者旧消息已登记回复承诺，但尚在排队或加载图片，没有
active run 可供接管。窗口内新消息替换 pending 后，旧 context 只检查当前 pending
的 cancel 值，读到新记录的 false，仍然继续执行。旧 context 的 abort/finish 还会
按 sender 无条件移除新 pending。

新增小型运行时 `TurnOwnership`，context 与自身 pending 共享归属 token。
窗口内被替换的旧承诺失效，token 随 context 存活，因此新 pending 被消费后旧任务
也不会恢复有效。abort/finish 仅清理自身 pending。活跃回合接管及窗口外独立请求
保留原语义，没有改判官、提示词、数据库、投递去重闸或窗口长度。

真实 RealContextPlugin 路径的 6 条回归使用本地临时 DB 和假 adapter，禁用网络
判官与反应操作。修前 1 条通过、5 条失败，修后 real_context 整组 52 条通过。

```bash
cargo test --lib platforms::plugins::real_context::tests
```

无法保证从未发生。本次不宣称修复所有 QQ 重复场景；工具前后正文重复（F6）及
