# TUI 会话列表布局与当前会话重复加载

## 现象与根因

空会话 `/session` 先调用 `live.suspend()`，该方法为外部终端输出清除大厅和输入框。随后的 inline 选择器从正文结束位置起笔；空正文对应屏幕左上角，因此整个大厅消失。非空会话的 inline 选择器直接向终端预留行，没有更新 Screen 持有的正文视口，无法像提问面板一样按实际高度推动和回翻正文。

选择器确认当前会话后仍调用 `GetSessionState` 和 `apply_repl_session_switch`，这会清空、回放正文并丢失当前阅读位置。相同会话无需切换。

## 修复

- 新增独立 `repl/session_picker.rs`，全屏选择器只负责交互与显示适配。复用已有 fuzzy 匹配、搜索/删除按键语义和条目/标题/帮助格式函数。普通 inline 入口保留。
- 空会话保留大厅、输入框和模式提示。面板从大厅提示下一空行后起笔，与输入框对齐。终端较矮时仅按所需空间上移大厅，列表按剩余高度裁剪。
- 非空会话复用 `Screen::scroll_question_body`，为面板、底部留白与正文分隔空行预留高度。PgUp/PgDn 和滚轮可回翻正文。
- 缓存终端尺寸与面板高度；光标移动和删除确认只画面板，搜索改变高度、缩放或回翻才重排正文/大厅。所有绘制仍在同步终端更新边界内，输出最终按实际显示列宽裁剪。
- 退出、取消或读取错误均恢复原输入框。选当前会话或显式指定当前编号/名称均不重新加载，保留正文缓冲和阅读位置。
- 面板接管输入期间也检查通知到期，连续按键和空闲等待均覆盖。只有通知实际消失时才使布局缓存失效并重画。

## 人工验收

1. 空会话执行 `/session`：大厅与输入框仍在，列表位于 `/config`、`/sandbox` 提示下面，与输入框左边对齐。
2. 搜索、方向键移动；Ctrl+D 后 Esc 应只取消删除确认，再 Esc 关闭列表。
3. 在长会话执行 `/session`：底部列表上方有一行空白，最后一段正文仍可见。用 PgUp/PgDn 回翻，再缩放终端。
4. 回翻到较早正文后选择当前带 `*` 的会话：列表关闭，阅读位置保持，无切换通知。选择其他会话应正常加载目标正文。
